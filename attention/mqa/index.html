What multi-query attention is

When a decoder generates text one token at a time, every layer keeps the keys and values of all earlier tokens, the KV cache, and each new token reads the whole cache in every layer. Shazeer (2019) pointed out that at this stage the time goes into loading those tensors from memory, not into arithmetic. Multi-query attention (MQA) keeps many query heads but gives all of them one shared key head and one shared value head, so the cache is as small as a single head's.

This page records it in SantaCoder (1.1B), a code model with 24 layers, of which every third is recorded, and 16 query heads of 128 dimensions that read 1 key head and 1 value head. The three prompts are code: Function arguments, Comprehension variable and JavaScript callback.

Compared with the MHA tab, only the head index on k and v is gone. The Query heads control in the toolbar draws all 16 query heads pointing at the one K and V. On the head card the Key and Value columns are marked “shared”: step through the query heads and they stay the same while the queries and the weight matrix change. Different heads still attend differently, because each asks its own question of the same keys. Clicking a K or V letter in the bank opens the projection of the one shared head, whichever query head is selected.

What it saves

Per token and layer, multi-head attention with these heads would cache 2×16×128=4,096 numbers for keys and values. MQA caches 2×128=256, sixteen times fewer. The projection shrinks with it: SantaCoder's fused Q, K, V matrix produces 2,048+128+128=2,304 numbers per token instead of 3×2,048. The query side is unchanged, 16×128=2,048, the model width.

At each decoding step a layer does little arithmetic, one new query against every cached key, but it has to read the whole cache from memory to do it, so the time per step follows the size of the cache. A smaller cache means each step reads less, and more sequences or longer contexts fit on one accelerator. Pope et al. found that on large PaLM models, with suitable partitioning across chips, the lower memory needs of multi-query attention allowed context lengths up to 32 times longer.

What it costs

Sharing one key and value head removes capacity: every head has to read from the same 128-dimensional summary of each token. Shazeer reported only minor quality degradation in his experiments; Ainslie et al. observed that MQA can lose quality and proposed grouped-query attention as the middle ground (the GQA tab). The training cost barely changes, since training processes all positions in parallel and is not bound by cache reads; the saving is at inference.

Where it came from

Shazeer introduced multi-query attention in 2019 as a fix for slow incremental decoding. PaLM (2022) used it at 540B parameters, and BigCode trained SantaCoder (2023), the model recorded here, with it. GQA (2023) generalised it to a few key and value heads; MLA (2024) compresses keys and values into a latent vector instead. The KV cache tab of the Efficiency Explainer shows the cache itself during prefill and decode.

  2. SantaCoder: don't reach for the stars! Loubna Ben Allal et al. · arXiv 2023 The 1.1B code model this page records, trained with multi-query attention.
