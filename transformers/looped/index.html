What a looped transformer is

A standard transformer gets deeper by adding layers, and every new layer brings new weights. A looped transformer runs the same stack of layers several times instead: the output of one pass is the input of the next, so depth grows while the number of parameters stays fixed. Each pass is called a loop.

This page records Ouro-1.4B, whose 24 blocks are applied 4 times with the same weights, on two prompts: If today is Monday, tomorrow is (7 tokens) and Water freezes at zero degrees (5 tokens). After each loop the model can read out a next-token distribution, and a small exit gate estimates whether it should stop there.

One stack, four passes

Write Fθ​ for the 24 blocks applied in order. Loop 1 starts from the token embeddings; every later loop starts from the previous loop's output after the final RMSNorm:

x(0)=E[tokens],x(r)=RMSNorm(Fθ​(x(r−1))),logits(r)=WU​x(r),r=1,…,4

The embeddings are not added again, and there is no per-loop embedding or norm. The band under the diagram, labelled ↺ Loop 2 of 4 and so on, carries the normalised state back to the input lane. The ‹ Loop 1 of 4 › stepper moves through the passes, and the block drawn is the same in each, only its input changes.

Each block is Llama-like with a "sandwich" of norms: an RMSNorm before attention and another on its output before the residual addition, x←x+RMSNorm(Attn(RMSNorm(x))), and the same around the SwiGLU MLP (2048 → 5632 → 2048). Attention is causal with 16 heads of 128 dimensions and RoPE with base 106. In loop r the keys and values come from loop r's own state, not from loop 1's.

Parameters versus compute

The Shared weights card counts the trade. One block has 51.4M parameters; the 24 blocks plus the embedding, LM head, gate and final norm make 1.43B. Each token goes through 96 block passes, about 3.8 times the matrix-multiply work of one pass (3.77 by the recorded count). A model that spent the same 96 passes on distinct blocks would need 5.13B parameters.

Looping saves weights, not compute or memory traffic. Each loop's attention needs its own keys and values, so the KV cache holds 96 entries per token, four times that of a single pass. The page's popup notes that the model card reports benchmark results comparable to standard transformers of 3–4B parameters.

Reading out after any loop

Because every loop ends in the same normalised space, the LM head can read any of them. The Stopping after each loop card shows the top tokens if the model stopped after loop 1, 2, 3 or 4. On the Monday prompt, loop 1's best guess is Wednesday at 0.75 %; after loop 2 it is Tuesday at 48.2 %, rising to 64.9 % after loop 3 and ending at 60.0 % after loop 4. On the water prompt Celsius is already the top token after loop 1, at 44.9 %, and the later loops raise it to 85.3 %, 84.0 % and 77.4 %. Extra loops change the answer on the first prompt and sharpen it on the second.

The exit gate

The exit gate is one linear map from 2048 dimensions to a single logit, 2,049 parameters shared by all loops. Its sigmoid is the probability of stopping after loop r if loop r was reached, and those conditional probabilities give an exit distribution over the four loops:

λr​=σ(w⋅x(r)+b),pr​=λr​j<r∏​(1−λj​)(r<4),p4​=j<4∏​(1−λj​),E[loops]=r∑​rpr​

The last loop takes all the remaining mass, so λ4​ is computed but not used (drawn hatched). At the last Monday token the gate puts 0.003 on loop 2, 0.35 on loop 3 and 0.65 on loop 4, an expected 3.64 loops; at the last water token the expectation is 3.27. A model would stop at the first loop whose cumulative exit probability reaches a threshold q. The released configuration sets q=1.0, so every position reads loop 4 and all four loops are always computed; a smaller q would let easy tokens stop early.

Where looping came from

The Universal Transformer (Dehghani et al., 2018) applied one transformer block repeatedly and let each position decide when to halt, using Graves's Adaptive Computation Time (2016), which learns halting probabilities for recurrent networks. PonderNet (Banino et al., 2021) made halting a probability distribution of exactly the form above and trained it with a regulariser towards a prior. ALBERT (2019) shared weights across layers to save parameters, without varying the depth.

Later work studied what looping buys: Saunshi et al. (2025) argue that a looped model of k layers run L times can match much deeper models on reasoning tasks, and Geiping et al. (2025) scale test-time compute by running a recurrent block more times. Ouro (Zhu et al., 2025) pretrains looped language models on 7.7T tokens with an entropy-regularised objective for the exit distribution. The Dense tab shows an ordinary 12-block stack in which every block has its own weights.
