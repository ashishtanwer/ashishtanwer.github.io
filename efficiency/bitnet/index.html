What BitNet b1.58 is

The other quantization tabs take a model trained in 16 bits and round it afterwards. BitNet b1.58 is trained with low-precision weights from the start: every weight of every linear layer is −1, 0 or +1, times one scale per matrix, and every linear layer's input is rounded to 8 bits per token. Three values carry log2​3≈1.58 bits of information, which gives the name. Because the weights are ternary, a matrix product needs no multiplications: each output adds some inputs, subtracts others and skips the rest.

This page records Microsoft's BitNet b1.58 2B4T, a 2-billion-parameter model trained on 4 trillion tokens (30 layers, a hidden size of 2,560 and squared-ReLU MLPs), with transformers' built-in BitNet code in float32 on this Mac's CPU. It features layer 15's down_proj (2,560 × 6,912) and compares it with Microsoft's bf16 master copy of the same weights.

Ternary weights

BitNet b1.58 quantizes a weight matrix with its absmean: the scale β is the mean absolute value of the full-precision weights, and each weight is divided by it, rounded and clipped:

β=nm1​ij∑​∣Wij​∣,Tij​=clip(round(Wij​/β), −1, 1),W^=βT

A weight becomes 0 when ∣W∣<β/2. In the featured matrix β=2.609, stored in bf16 as weight_scale, and 39.8 % of the weights are 0, 30.1 % are +1 and 30.1 % are −1. The Ternary weights panel switches between the released ternary weights and the bf16 master copy. Applying the rule to the master copy gives the stored weight for 97.50 % of the matrix; the other 442,463 all have ∣W∣=1.3047, where ∣W∣/β=0.4994, within one bf16 step of the rounding point β/2, so the bf16 copy cannot tell which side the training weights were on.

The file packs four ternary weights into a byte, each stored as weight + 1 in 2 bits; the Bits per weight panel sets those 2 bits against 16 for bf16 and the 1.58 bits of information.

A matrix product without multiplications

The layer's input x is quantized per token with its absmax γ=max∣x∣ to integers xq​=round(127x/γ). One output of the layer is then

yi​=127βγ​(j:Tij​=+1∑​xq,j​−j:Tij​=−1∑​xq,j​)

an integer sum and difference, then one multiplication by the two scales. The A matrix product without multiplications panel computes output 1024 for the last prompt token: γ=42.74; 2,104 inputs have weight +1 and sum to 556, 2,053 have weight −1 and sum to −864, and 2,755 are skipped. The result, 1,247, matches the model's own down_proj output to 0.00049. bitnet.cpp's kernels exploit this structure; PyTorch here multiplies by the ternary values as ordinary floats.

The Share of zero weights strip shows that across all 210 ternary matrices between 36 % and 60 % of the weights are zero, inputs that every product skips outright.

Training with ternary weights

Rounding has zero gradient almost everywhere, so BitNet keeps a full-precision copy of every weight during training. The forward pass uses the ternary weights and 8-bit activations; the backward pass treats the rounding as the identity, the straight-through estimator, and the optimiser updates the full-precision copy:

∂W∂L​≈∂W^∂L​,W←W−η∂W∂L​

After training only T and β are kept. The bf16 master copy on this page is that copy, released separately and rounded to bf16, which is why it cannot settle the weights that lie at β/2; the ternary file is what is meant to run.

What the model says

"8-bit inputs" in the What the model says panel is the model as trained, with ternary weights and every linear layer's input rounded to 8 bits; "unrounded inputs" keeps the same weights and skips only that rounding. Both answer "The capital of Australia is Canberra."; with unrounded inputs the model goes on to a second sentence. Their next-token distributions differ by a KL divergence of 1.7×10−6 nats, and their WikiText-2 perplexities are 21.54 and 21.57. These use the model's Llama 3 tokenizer, so they do not compare with the Qwen tabs' perplexities.

The file is 1,179 MB: 657 MB is the bf16 embedding, shared with the output layer, and 521 MB holds the 2.08 billion ternary weights packed at 2 bits each. At this size the embedding, not the transformer, takes most of the memory.

Where it came from

Bengio et al. (2013) studied the straight-through estimator for training through hard thresholds, and ternary weight networks (2016) trained image classifiers with weights in {−1,0,+1} and a scale. BitNet (2023) introduced BitLinear, a drop-in replacement for the linear layer, and trained transformer language models from scratch with binary weights. BitNet b1.58 (2024) added the zero and the absmean scale, and its paper reports matching a full-precision transformer of the same size and training tokens in perplexity and end-task performance. The 2B4T report (2025) released the model on this page, and bitnet.cpp (2024) the CPU kernels that compute its products with additions.
